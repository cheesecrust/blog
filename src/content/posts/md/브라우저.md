
## 이벤트 기초

### 버블링
event 가 발생하면 가장 최상단의 요소(`document` , `window`)를 만날때까지 이벤트가 전파 되는것 입니다.

> 이벤트가 발생한 요소로 부터 최상단의 요소까지 이벤트가 전파 됩니다.
   이에 따라 해당하는 핸들러 들을 트리거 시킬 수 있다.

> 모든 이벤트가 버블링 되는것은 아니고 **대부분**의 이벤트가 버블링 됩니다. 
> 이 뜻은 버블링이 되지 않는 이벤트도 존재 합니다.

이러힌 버블링을 중단하기 위해서 `eventStopPropagation()` 을 사용한다.
하지만 이를 잘 사용하지는 않는데, 상위의 이벤트 트리거가 필요한 경우가 종종 생기기 때문입니다.

### 캡쳐링
이는 버블링과 반대로 이벤트가 발생할 시, 요소의 위에서 부터 타깃 요소까지 이벤트가 타고 내려오는 것입니다.
이때 이벤트를 낚아채서 handler 를 트리거 하기 위해서는 option 을 부여해야 합니다.

### 실행흐름
이벤트는 발생 시점에 객체로 생성되고, DOM을 따라 전파되며, 그 경로에서 등록된 이벤트 리스너들이 순서대로 실행된다

이때 위에서 부터 내려오는 이유는 이벤트 흐름을 가로챌 수 있는 부분을 두 곳을 만들어 두기 위함, 사실 target 부터 시작해서 버블링 만을 구현 할 수도 있지만, 기회를 주기 위해 위에서 부터 내려오는 구조를 택했습니다.

## e.preventDefault()

이는 브라우저의 기본동작을 막는 함수 입니다. 
이때 브라우저의 기본 동작은 이벤트 실행 흐름 뒤에 따로 브라우저에서 동작하기 때문에, 버블링을 막거나 등을 하는것이 효과가 없습니다.

## 브라우저 실행 순서

브라우저가 V8 엔진을 통하여 JS 를 실행시키는 순서

1. **콜스택** (동기 코드)
	DOM commit 까지 마칩니다. 일반적인 code 와 DOM contorl 이 실행되는 단계
2. **마이크로태스크** (Promise.then, MutationObserver)
3. **브라우저 렌더링** (페인트)
   style -> layout -> paint -> composite
   이때 render tree 를 만들고 이를 기준으로 화면을 그립니다.
4. **매크로태스크** (setTimeout, setInterval, useEffect)

> 하지만, 이때 별도의 단계로 `requestAnimateFrame` 의 단계가 있다.
