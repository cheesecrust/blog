## 리랜더링

보통의 리랜더링은 **state** 값이나 **store** 값이 변경되었을 때 일어납니다.

## useEffect

`useEffect`는 랜더링 된 후 **사이드 이펙트**를 컨트롤하는 hook 입니다.

- 따라서 의존하는 변수의 값이 변동될 때에 실행되며
- 끝났을 때의 **cleanup 함수**를 callback 으로 지정합니다.

## Hook 

같은 hook 을 호출하게 되면 각각의 component 별로 이에 해당하는 메모리를 할당합니다.
따라서 같은 hook 을 호출하더라도 같은 내용으로 따로 따로 각각의 호출한 component 에 맞춰서 할당되고 맞춰집니다.

hook 에서 useRef 로 요소가 할당되는 경우는 인자로 들어갔을때 .current 에 자동으로 할당 할 수 있습니다.
hook 은 JSX 안에서 호출 할 수 없다.

각 컴포넌트 인스턴스 마다 Fiber 라는 노드가 있고, 그 안에 hook list 가 붙어있다.

## Event Listener & Event Handler

### EventListener

요소에 등록 되며, 해당 요소에서 이벤트가 발생하면 브라우저가 등록된 핸들러를 호출한다.

```
이벤트 발생 -> 리스너 확인 -> 리스너에 등록 된 핸들러 실행
```

위처럼 동작하며, 핸들러를 호출하는 주체는 **리스너가 아닙니다.**
리스너는 단지 이벤트와 연결된 handler 가 뭔지 알려주는 역할 입니다.

### 리스너가 여러개 라면 누가 먼저 실행될까?

같은 요소 같은 이벤트의 경우에는 코드상으로 등록된 순서대로 실행됩니다.

### React 에서의 이벤트 리스너

### 이벤트 위임
이벤트 리스너를 각 요소마다 붙이는 것이 아닌, root 에 모아 등록하는것.
이의 장점으로는 동적 랜더링 대응이 있습니다. 
또한 Synthetic Event 와 같이 움직이는데에 있어서 이점이 있습니다.

### Synthetic Event

react 가 만든 표준화된 이벤트 객체 입니다. 각각의 브라우저마다 정의한 이벤트가 다르기 때문에 이벤트를 한번 묶는 형식입니다.

이는 react 방식으로 핸들러를 등록 할때만 붙게 됩니다.

## Lint 관련

렌더링 중에 `ref` 로 접근하면 안됨

```javascript
	...
	const test = () => {
		// 안에서 ref 접근
	};
	
	return {fooProps(test)};

```

위 처럼 ref 접근을 하는 함수를 props 인자로 넘길떄 함수를 반환할때 해당 함수에서 ref 를 접근한다면, 이 ref 를 접근하는 함수가 렌더중에 일어날 수 있다고 판단합니다.

따라서 이를 이쁘게 고치는 법은 아래와 같습니다.
```javascript
	...
	const test = () => {
		// 안에서 ref 접근
	};
	
	return {..fooProps, test: test};

```
